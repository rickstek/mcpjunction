# mcpjunction.ai

Self-maintaining MCP server directory. A nightly GitHub Action refreshes the
dataset from the GitHub API, rebuilds the sitemap, commits the diff, and
redeploys the Cloudflare Worker. Nobody uploads a zip again.

```
public/                      ← this folder IS the website (Worker asset root)
  index.html                 ← copy from your live site (pull_live.sh)
  licensing.html             ← copy from your live site
  license.xml                ← copy from your live site (RSL terms)
  llms.txt                   ← copy from your live site
  robots.txt                 ← in repo; source version, see note below
  404.html                   ← in repo
  sitemap.xml                ← GENERATED by scripts/build_sitemap.py
  data/mcp_servers.json      ← GENERATED by scripts/pipeline.py
  data/mcp_servers.csv       ← GENERATED
scripts/
  pipeline.py                ← GitHub API → normalized dataset (merges, never clobbers)
  build_sitemap.py           ← emits only URLs that actually exist
  pull_live.sh               ← one-time: mirror the live site into public/
wrangler.jsonc               ← Worker config (name MUST match existing Worker)
.github/workflows/nightly.yml
```

## First-time setup

1. **Create the repo** (private is fine) and copy these files in.
2. **Mirror production:** `bash scripts/pull_live.sh` — the Worker serves only
   what's in `public/`, so anything live but missing here gets deleted from the
   site on the first deploy.
3. **Set the Worker name** in `wrangler.jsonc` to the exact existing name.
4. **Cloudflare API token:** dash.cloudflare.com → My Profile → API Tokens →
   Create Token → *Edit Cloudflare Workers* template → scope it to this account
   and to the mcpjunction.ai zone. Copy it once; it's never shown again.
5. **GitHub secrets** (Settings → Secrets and variables → Actions):
   - `CLOUDFLARE_API_TOKEN`
   - `CLOUDFLARE_ACCOUNT_ID` (Cloudflare dashboard → Workers & Pages, right sidebar)
   No GitHub PAT needed — the workflow's built-in `GITHUB_TOKEN` authenticates
   the API calls.
6. **Dry run:** Actions tab → *Nightly refresh and deploy* → Run workflow, with
   **skip_data_refresh = true**. This deploys the current files without touching
   the GitHub API, so if the Worker name is wrong you find out in 60 seconds
   with nothing at stake.
7. **Real run:** re-run with the box unchecked. Then check
   `https://mcpjunction.ai/data/mcp_servers.json` for a fresh `generated_at`
   and `https://mcpjunction.ai/sitemap.xml` for a 200 instead of a 404.

## Guardrails baked in

- **Editorial fields are human-only.** `security_reviewed`, `verified_badge`,
  `sponsor_tier`, and `editorial_notes` are carried forward from the previous
  dataset and never written by the pipeline. Automation cannot grant a badge or
  a security clearance. Set them by hand in `public/data/mcp_servers.json` and
  commit; the next nightly run preserves them.
- **Collapse guard.** The deploy aborts if the dataset drops below 200 servers.
  A bad GitHub API day shouldn't silently gut a directory other people cite.
- **No dead links.** The sitemap lists only files present on disk at build time.
- **Delisted repos persist 30 days** as `status: archived_or_removed`
  (timestamped in `delisted_at`), then drop — stable URLs without unbounded
  dataset growth.
- **CSV injection guard.** Any published CSV cell starting with `= + - @` is
  prefixed with `'` so repo descriptions (attacker-controllable — anyone can
  name a GitHub repo) can't execute as spreadsheet formulas.
- **Install hints never auto-confirm.** No `npx -y` / `--yes` flags: the
  registry package sharing a repo's name may be squatted by someone else.
  Hints are labeled as unverified in the dataset disclaimer.
- **API ToS.** Official GitHub REST API only, authenticated, rate-limit aware.
  Public repo metadata only.

## robots.txt

`public/robots.txt` is self-contained and authoritative. It carries the Content
Signals policy text inline, the AI-crawler groups, **and** the `Sitemap:` and
`License:` directives.

**Cloudflare's "managed robots.txt" must stay OFF for this zone.** It is
documented as prepending its block to your file, but observed behaviour was
that it *replaced* the file outright — which silently dropped the `License:`
pointer to `license.xml`, breaking RSL discovery, and the `Sitemap:` line.
Turning it off costs nothing: the Content Signals policy is in our file, and
actual enforcement comes from AI Crawl Control, which is a separate feature and
stays enabled.

Verify after any Cloudflare bot-settings change:

    curl -s https://mcpjunction.ai/robots.txt | tail -5

You should see the `Sitemap:` and `License:` lines. If the output ends at
`# END Cloudflare Managed Content`, managed robots.txt got re-enabled.

## When to change posture

Current stance: search allowed, agents allowed free, training blocked/licensed.
The flip to Pay Per Crawl on `/data/` plus RSL `ai-input` → paid happens when
Cloudflare bot analytics show several thousand agent hits/month — not before.
Quarterly review either way.
